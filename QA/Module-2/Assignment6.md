## Tool Mapping Table

| Tool                      | Purpose in Validation Workflow                                                                               | Conditions / Use Cases                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ------------------------- | ------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Wireshark**             | Deep packet analysis for protocol‑level debugging, RF issues, and application behaviour.                     | • When analysing VoIP call quality issues (SIP/RTP packet loss, jitter).<br>• When debugging DHCP/DNS/ARP failures during client association.<br>• When investigating 802.11 retransmissions or RTS/CTS behaviour.<br>• When analyzing WLC ↔ AP CAPWAP control/ data plane traffic.                                                                                                                                                          |
| **Airtool**               | macOS‑based Wi‑Fi packet capture and RF monitoring; captures raw 802.11 frames in monitor mode.              | • When performing channel‑specific capture to analyse Wi‑Fi retries, signal strength, or interference at the RF layer.<br>• When capturing 802.11 management frames (probes, beacons, auth/assoc) for client behaviour analysis.<br>• When validating roaming behaviour across APs (captures on specific channels).                                                                                                                          |
| **Port Mirroring (SPAN)** | Mirrors switch traffic to a monitoring port for non‑intrusive analysis without affecting production.         | • When capturing wired traffic between WLC and APs (CAPWAP tunnels) or backhaul traffic.<br>• When monitoring wired‑side latency or packet loss without deploying probes on every link.<br>• When analysing traffic to/from the core switch without impacting performance.                                                                                                                                                                   |
| **TCPDump**               | Lightweight CLI packet capture on Linux servers or embedded devices (APs, WLC).                              | • When running packet captures on headless/embedded devices (APs or WLC) where GUI tools aren't available.<br>• When capturing CAPWAP or ICMP traffic in resource‑constrained environments.<br>• When automating captures via scripts for long‑term monitoring.                                                                                                                                                                              |
| **TRex**                  | High‑performance, stateful traffic generator – simulates millions of concurrent flows, line‑rate throughput. | • When stress‑testing the network infrastructure (switches, routers, firewalls) with realistic stateful traffic.<br>• When measuring PPS (packets per second) capacity of the wired backhaul under multi‑client loads.<br>• When validating QoS / DSCP marking for VoIP and video traffic end‑to‑end.                                                                                                                                        |
| **VeriWave**              | Enterprise‑grade Wi‑Fi test platform; simulates hundreds of wireless clients (802.11a/b/g/n/ac/ax).          | • When testing client scalability – validating WLC can handle 1000+ clients with stable associations and roaming.<br>• When validating roaming performance (inter‑AP handoff latency, packet loss during roam).<br>• When testing multi‑client scenarios: 100 simultaneous VoIP calls, 20 video streams, mixed traffic types.<br>• When performing regression testing of new firmware under high client density.                             |
| **iPerf**                 | Active throughput measurement for TCP/UDP; measures bandwidth, jitter, packet loss, retransmissions.         | • When measuring point‑to‑point throughput between clients and servers (e.g., file download performance).<br>• When benchmarking UDP performance for VoIP/video traffic (jitter, loss at different bitrates).<br>• When validating bandwidth allocation with QoS policies (e.g., 100 Mbps per client limit).<br>• When testing bidirectional throughput (client ↔ server, AP ↔ WLC).                                                         |
| **Multicast Hammer Tool** | Specialised tool for generating and testing multicast/broadcast traffic in Wi‑Fi environments.               | • When validating multicast performance in a WLAN (e.g., IPTV, push notifications, mDNS/Bonjour).<br>• When measuring multicast group join/leave latency and packet delivery reliability.<br>• When testing impact of multicast traffic on unicast performance (Wi‑Fi multicast-to-unicast conversion).<br>• When ensuring multicast traffic doesn't flood the network or cause AP over‑subscription.                                        |
| **Octoscope**             | Wi‑Fi network testing platform – client simulation with application‑aware traffic (VoIP, video, data).       | • When performing comprehensive multi‑client performance tests (e.g., 100 clients each running VoIP + data).<br>• When validating application performance under real‑world traffic mixes (web browsing + video + file downloads).<br>• When running regression tests against firmware versions with automatic pass/fail thresholds.<br>• When generating custom traffic profiles that match customer environment (20 APs, 1000 clients).     |
| **IXIA – IXChariot**      | End‑to‑end application performance testing; emulates real‑world applications (HTTP, FTP, VoIP, video).       | • When measuring application‑level quality metrics (response time, throughput, jitter) across the WLAN.<br>• When validating QoS policies for different application classes (e.g., priority for VoIP over web traffic).<br>• When testing multi‑endpoint scenarios: 100 clients browsing, 50 VoIP calls, 20 video streams simultaneously.<br>• When generating custom scripts for continuous integration/regression testing of new firmware. |
